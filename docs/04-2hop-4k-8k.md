# 04 — 2hop at 4K/8K + the OOM fix

## Result

- **2160p60 av01**: stable, indefinite — recommended production ceiling on
  phones.
- **4320p60 HDR av01** (itag 702, ~4GB stream): verified playing; longest observed run reached ~15 min before iOS killed the renderer (decoder memory: ~130MB per decoded 7680x4320 frame). Longer runs untested; treat 2160p as the practical ceiling.

## The OOM and its fix

First 4320p tests crashed the tab in ~5s — much earlier than the decoder
limit above. Cause: the SW proxy forwarded **unbounded** bodies. When the
element sends `Range: bytes=X-` (open-ended), the opaque response streams
the entire remaining file through the worker → GBs in flight → OOM.

Fix: **clamp every proxied response to a bounded window** (~8MB):

```js
// in the /gv handler
const range = e.request.headers.get("range");
let start = 0, end;
if (range) {
  const m = /bytes=(\d+)-(\d*)/.exec(range);
  start = +m[1];
  end = m[2] ? +m[2] : null;
}
const CLAMP = 8 * 1024 * 1024;
const winEnd = Math.min(end ?? Infinity, start + CLAMP - 1);
const upstream = await fetch(real, {
  mode: "no-cors",
  headers: { Range: `bytes=${start}-${winEnd}` },
});
```

The element just asks for the next window when it runs out — memory stays
flat. With the clamp, 4320p60 went from 5s crash to ~15min playback.

## Mid-clip seek at 8K

VISIONOS ranges are fully unlocked: seeks 6.5s→123s→889s→48s all resumed
instantly through the proxy, audio followed. Treat seek as "set
currentTime, let the element re-request its windows".

## Watchdog details that matter

- Death test = `totalVideoFrames` frozen AND `currentTime` frozen across
  consecutive polls (~2-4s each, N≈3-6). Everything else lies on iOS.
- Counters reset after suspend — never compare absolute frame counts across
  suspend/resume.
- Off-viewport decoders get suspended with `paused` possibly false and zero
  events — do not descend the ladder for that.
- Restart-on-same-element can take ~10-15s to reach `loadedmetadata` on big
  rungs — backstop with a `canplay` timeout, don't abort early.
- Winner arbitration for shared audio: crown the pane producing decoded
  frames, not the first to emit `playing` (a stalled element can emit
  `playing` with 0 frames).

## Audio sync at high res

Same-dedicated-iframe `<audio>` element. Resync on `seeked` and when drift
>0.35s. At 4320p60 audio stayed within ±0.3s of video for the whole run.

## Bandwidth note

6 concurrent HD rungs through one proxy starve each other — that's test
harness load, not a production concern. Single-stream playback is
unaffected at every resolution YouTube offers.
